# -absentee_rate
欠課時数確認アプリ
欠課時数チェック GitHubの使い方ガイド
このガイドは、パソコンにあまり詳しくない人でも、順番に進めれば迷わないように書いています。分からない言葉が出てきたら、いちばん上の「先に覚える言葉」を見てください。
先に覚える言葉
•	GitHub（ギットハブ）：インターネット上の「ファイルの置き場」です。
•	リポジトリ：ファイルを入れておく「箱」です。この仕組みでは、箱を2つ使います。
•	Public（公開）：誰でも中を見られる箱です。
•	Private（非公開）：自分だけが見られる箱です。
•	コミット（Commit changes）：「保存する」ボタンのことです。
•	トークン：アプリがGitHubの箱を開けるための「合い鍵」です。パスワードと同じくらい大切なので、人に見せません。
全体の流れ
箱を2つ作ります。
1.	アプリ用の箱（Public）：アプリ本体の index.html を入れます。名前の例は kekka-check です。
2.	データ用の箱（Private）：生徒の記録（仮名）が自動で保存されます。名前の例は kekka-data です。
そして、アプリが2つ目の箱に保存できるように、トークン（合い鍵）を1つ作って、アプリに貼り付けます。
生徒の名前（実名）は、アプリにもGitHubにも入れません。 「Iさん」「Oさん」のような仮名だけを使います。
パート1　アプリを公開する（はじめての1回だけ）
1-1　アプリ用の箱を作る
1.	GitHubを開いてログインします。
2.	画面の右上にある「+」のマークを押し、「New repository」を選びます。
3.	「Repository name」の欄に、名前を入れます。英語と数字だけにしてください。例: kekka-check
4.	「Public」を選びます。
5.	「Add a README file」にチェックを入れます。
6.	緑色の「Create repository」を押します。
1-2　index.html をアップロードする
1.	作った箱の画面で、「Add file」を押し、「Upload files」を選びます。
2.	パソコンに保存してある index.html を、画面の枠の中にドラッグして入れます。ファイルの名前は、必ず index.html のままにしてください。
3.	画面の下にある緑色の「Commit changes」を押します。これで保存できました。
1-3　アプリをインターネットに公開する（GitHub Pages）
1.	箱の画面の上にある「Settings」を押します。
2.	左のメニューから「Pages」を選びます。
3.	「Build and deployment」の中の「Source」を「Deploy from a branch」にします。
4.	「Branch」を「main」にし、その横を「/ (root)」にして、「Save」を押します。
1-4　公開されたアプリを開く
1.	1〜3分ほど待ってから、「Pages」の画面を読み込み直します。
2.	「Your site is live at ...」と表示され、アドレスが出ます。
3.	アドレスの形は、https://あなたのユーザー名.github.io/kekka-check/ です。
4.	このアドレスを開くと、アプリが動きます。ブックマークや、スマホのホーム画面に追加しておくと便利です。
パート2　アプリを書き直す（新しい index.html をもらったとき）
新しい index.html をもらったら、同じ名前で上書きするだけです。
1.	GitHubで、アプリ用の箱（kekka-check）を開きます。
2.	「Add file」→「Upload files」を押します。
3.	新しい index.html をドラッグして入れます。ファイル名は必ず index.html のままにします。同じ名前のファイルは、自動で上書きされます。
4.	画面の下の「Commit changes」を押します。
5.	1〜2分待ちます。
6.	アプリのアドレスを開き、ページを強制的に読み込み直します。
o	パソコン：Ctrl と Shift を押したまま R を押します（Macは Command と Shift と R）。
o	スマホ：ブラウザのタブをいったん閉じて、開き直します。
古いままのときは
•	まだ1〜2分たっていないかもしれません。少し待ってから、もう一度強制読み込みをします。
•	アップロードしたあとに「Commit changes」を押し忘れていないか、確認します。
•	間違って上書きしたときは、箱の画面で index.html を開き、右上の時計のマーク（History）から、前の状態を見ることができます。
作り直しても、生徒のデータは消えません
生徒のデータは、アプリ用の箱ではなく、パート3で作るデータ用の箱に保存されます。index.html を上書きしても、データはそのまま残ります。
パート3　データ用の非公開の箱を作る
1.	GitHubの右上の「+」→「New repository」を押します。
2.	名前を入れます。例: kekka-data
3.	必ず「Private」を選びます。 Publicにすると、誰でも中を見られてしまいます。
4.	「Add a README file」にチェックを入れます。 空の箱だと、うまく保存できないことがあるためです。
5.	「Create repository」を押します。
パート4　トークン（合い鍵）を作る
トークンは、データ用の箱（kekka-data）1つだけを開けられる鍵として作ります。
1.	GitHubの画面の右上にある、丸い自分のアイコンを押します。
2.	出てきたメニューから「Settings」を選びます。
3.	左のメニューを一番下までスクロールし、「Developer settings」を押します。
4.	左のメニューの「Personal access tokens」を押し、「Fine-grained tokens」を選びます。
5.	右上の「Generate new token」を押します。パスワードを聞かれたら、入力します。
6.	「Token name」に、分かりやすい名前を入れます。例: kekka-app
7.	「Expiration」は、鍵の使える期限です。90日などを選びます。期限が切れたら、同じ手順で作り直します。
8.	「Resource owner」は、自分のユーザー名のままにします。
9.	「Repository access」で「Only select repositories」を選びます。出てきた選択欄から、データ用の kekka-data だけを選びます。アプリ用の箱は選びません。
10.	「Permissions」の中の「Repository permissions」を開き、たくさんある項目の中から「Contents」を探して、「Read and write」にします。ほかの項目は、さわらなくて大丈夫です。
11.	一番下の緑色の「Generate token」を押します。確認の画面が出たら、もう一度押します。
12.	「github_pat_」で始まる長い文字列が表示されます。横のコピーマークを押して、コピーします。この文字列は、画面を閉じると二度と見られません。 すぐに次のパートに進んでください。
パート5　アプリとデータ用の箱をつなぐ
1.	アプリを開き、右上の「同期設定」を押します。
2.	次のように入力します。
o	「GitHubのユーザー名」：自分のGitHubのユーザー名
o	「データ用リポジトリ名」：kekka-data
o	「保存するファイル名」：data.json のまま
o	「トークン」：さっきコピーした文字列を貼り付けます
3.	自分のパソコンなら、「このPCにトークンを記憶する」にチェックを入れます。学校の共有パソコンでは、チェックを入れません。
4.	「接続する」を押します。
5.	画面の右上の表示が「GitHub保存済み」になれば、成功です。
ほかのパソコンで使うとき
ほかのパソコンでも、アプリのアドレスを開き、同じ設定（ユーザー名・kekka-data・トークン）を入れれば、同じデータが出ます。トークンは、コピーしておいたものをもう一度貼り付けます。なくしたときは、パート4をやり直して、新しいトークンを作ります。
パート6　毎日の使い方
1.	アプリを開きます。右上が「GitHub保存済み」になるのを確認します。
2.	生徒を追加するときは、仮名（例: Iさん）を入れて「生徒を追加」を押します。
3.	科目の選択画面で、課程と学年を選び、その生徒が取っている科目にチェックを入れます。
4.	授業時数と出席時数を入力します。
5.	入力すると、約1.5秒後に自動で保存されます。保存ボタンはありません。
6.	保護者や生徒に見せる資料は、その生徒の名前の欄に名前を入れて「資料を出力（PDF）」を押し、「PDFに保存」を選びます。名前の欄は保存されません。
7.	学年が変わるときは、「科目を選ぶ」から学年を選び直します。それまでの記録は「過去の学年の記録」に自動で残ります。
困ったときは
•	ページが古いまま：パート2の強制読み込みをします。
•	同期エラー 401 と出る：トークンが間違っているか、期限が切れています。パート4で作り直して、パート5に貼り直します。
•	同期エラー 404 と出る：ユーザー名かリポジトリ名の打ち間違いか、トークンで選んだ箱が違っています。名前と、トークンの「Repository access」を確かめます。
•	同期エラー 403 と出る：トークンの「Contents」が「Read and write」になっていません。トークンを作り直します。
•	「公開のリポジトリです」と言われる：データ用の箱がPublicになっています。Privateの箱を新しく作ってください。
•	「競合」と出る：別のパソコンなどで先に更新されています。画面に出る2つのボタンから、使うほうを選びます。
•	トークンをなくした、人に見せてしまった：GitHubのトークン一覧で、そのトークンを削除し、パート4で新しく作ります。
必ず守ること
•	トークンは、人に教えません。メールやチャットにも貼りません。
•	生徒の実名は、アプリにも、箱にも、ファイル名にも入れません。仮名だけを使います。
•	書き出した backup のファイルやCSVには、仮名が入っています。アプリ用の箱（Public）には、絶対にアップロードしません。
•	学校の共有パソコンで使ったあとは、同期設定の「この端末のデータを消す」を押します。パソコンの中のデータとトークンが消えます。GitHubにあるデータは、消えません。
